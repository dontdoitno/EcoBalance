# ADR-0001: Выбор стека и структуры монорепозитория

- Статус: принято
- Дата: 2026-10-26

## Контекст

EcoBalance пересобирается из прототипа (Vite+React+JS, localStorage,
плоский расчёт) в рабочий прототип для акселератора: Next.js + FastAPI
монорепо с методологически корректным расчётным ядром.

## Решение

- Монорепозиторий: `apps/web` (Next.js 15, React 19, TypeScript strict,
  Tailwind, shadcn/ui), `apps/api` (FastAPI, Pydantic v2, SQLAlchemy 2.0
  async, PostgreSQL 16), `packages/contracts` (OpenAPI → TS клиент).
- JS-воркспейс управляется `pnpm` (`pnpm-workspace.yaml` в корне).
  **ASSUMPTION**: исходное ТЗ не называет JS package manager явно
  (только `uv` для Python) — выбран `pnpm` как стандартный инструмент
  для такой структуры монорепо.
- Python-зависимости — через `uv`; `ruff` + `mypy --strict` + `pytest`.
- Расчётное ядро `ecobalance_core` — отдельный пакет без зависимостей от
  FastAPI/БД, на `Decimal`/типизированном `float` с явным округлением
  только на выводе (решение откладывается до Этапа 1, где будет видно,
  какой вариант проще тестировать для golden-кейсов).
- PostgreSQL 16 через `docker-compose`; Alembic для миграций (Этап 2).
- Документация — `mkdocs-material`, формулы через KaTeX/MathJax,
  диаграммы — mermaid2.
- Отчёты — WeasyPrint (PDF) + `openpyxl` (XLSX), без клиентского
  рендеринга PDF.

## Статус старого прототипа

`src/`, `img/`, корневой `package.json`/Vite-конфиг остаются как UX-референс
(см. раздел 2 исходного ТЗ) до замены новым `apps/web`; не удаляются в
Stage 0.

## Последствия

- Два независимых набора зависимостей (корневой legacy Vite-проект и
  `apps/web`) существуют параллельно до миграции — временная избыточность,
  осознанно принята.
- Все версии зависимостей фиксируются для воспроизводимости (нефункц.
  требования, раздел 12 исходного ТЗ).
