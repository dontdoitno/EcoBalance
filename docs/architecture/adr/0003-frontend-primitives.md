# ADR-0003: внутренние UI-примитивы вместо shadcn/ui CLI

- Статус: принято
- Дата: 2026-10-29

## Контекст

Исходное ТЗ (§3) называет shadcn/ui (Radix) частью стека фронтенда.
Полноценная установка через shadcn CLI добавляет генератор компонентов,
собственный `components.json`, зависимость от конкретной версии Radix
на каждый примитив — заметный объём плюс сопровождения для одного
прохода сборки MVP.

## Решение

`apps/web/components/ui/` — небольшой набор примитивов (`Button`,
`Input`/`Select`/`Label`/`FieldError`, `Card`, `RatingBadge`),
построенных прямо на Tailwind + CSS-переменных дизайн-токенов
(`app/globals.css`). Доступность обеспечена построением: видимые
`:focus-visible`-кольца через глобальный токен, `<label htmlFor>`,
семантические `<button>`/`<select>`, читаемый контраст по токенам.

## Последствия

- Функционально эквивалентно тому, что нужно для MVP; легко заменить
  позже на shadcn/ui или другую библиотеку — примитивы инкапсулированы
  за собственным API (`<Button variant="primary">`, не
  Tailwind-классы в разметке страниц).
- Не получены «бесплатно» более сложные паттерны Radix (Dialog,
  Popover, Combobox) — в текущем UI они не понадобились (мастер и
  страницы результатов не используют модалки).
- Если проект продолжится, переход на shadcn/ui — чистая замена
  реализации примитивов без изменения вызывающего кода.
