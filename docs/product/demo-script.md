# Демо-сценарий (5 минут)

Подготовка: `make demo` (миграции + сид). Откройте http://localhost:3000.

## 1. Лендинг (30 сек)

Покажите hero и подвигайте слайдеры мини-калькулятора в блоке
«проблема» — покажите, как переплата растёт с ростом наценки
default-значения. Прокрутите до блока «Реальный пример расчёта» —
подчеркните, что это настоящий вывод ядра, не иллюстрация.

## 2. Вход демо-пользователем (15 сек)

`demo@ecobalance-demo.ru` / `demo12345`. Попадаете на `/dashboard` — три
демо-расчёта уже посчитаны (аммиак SMR, ПВХ суспензионный, мочевина с
улавливанием CO₂) — но под разными демо-компаниями
(`scripts/seed.py` создаёт каждую демо-компанию с собственным
пользователем); для показа списка расчётов именно demo-компании
достаточно одного расчёта (аммиак SMR), остальные два — для
демонстрации изоляции между компаниями при желании.

## 3. Новый расчёт (90 сек)

«Новый расчёт» → мастер:

1. Продукт: **Аммиак**, маршрут **SMR** — покажите баннер
   «входит в категории CBAM».
2. Сырьё: **Природный газ (сырьё)**, 0.6 т/т; электроэнергия 0.2 МВт·ч/т,
   регион **ОЭС Центра**.
3. Транспорт (опционально) — пропустите или добавьте одно плечо.
4. Подтверждение → «Рассчитать».

## 4. Результаты (60 сек)

Покажите карточки PCF full (3378,4 кг CO₂-экв./т) и CBAM embedded
(3297,4 кг CO₂-экв./т — обратите внимание, что он меньше PCF full на
величину транспорта), диаграмму разбивки, таблицу hotspots (Scope 1 и
сырьё — критические, по рейтингу с иконкой, не только цветом). Баннер
демо-коэффициентов.

## 5. Сценарий оптимизации (60 сек)

«Построить сценарий» → выберите **«Переход на электроэнергию с низким
EF»** и, если добавляли транспорт, **«Оптимизация логистики»** →
«Пересчитать сценарий». Покажите диаграмму «до/после» и дельту — это
настоящий повторный расчёт ядра на изменённых входных данных, не
процент, применённый к результату.

## 6. Отчёт (30 сек)

«Скачать отчёт» → PCF PDF и CBAM PDF — покажите, что для
CBAM-неприменимого продукта (например, если бы выбрали ПВХ) система
прямо отказывается с объяснением вместо подмены отчёта.

## Запасной путь: company isolation

Если нужно показать изоляцию данных между компаниями — зарегистрируйте
второй аккаунт (другой email) и попробуйте открыть URL чужого расчёта
по id — API вернёт 404.
