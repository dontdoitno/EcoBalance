# Открытые вопросы и допущения (ASSUMPTION)

## Stage 0

- **ASSUMPTION**: JS package manager — `pnpm` (workspaces через
  `pnpm-workspace.yaml`). Исходное ТЗ называет `uv` для Python, но не
  фиксирует JS-инструмент. Пересмотреть, если появятся явные указания.
- **ASSUMPTION**: стоп-слова для `check-clean` пока не заданы —
  `.stopwords.local` пуст (шаблон из `.stopwords.local.example`).
  Пользователь внесёт список позже; до этого `make check-clean` проходит
  тривиально.
- **ASSUMPTION**: дизайн-скилл `impeccable` недоступен в текущем окружении
  Claude Code на момент Stage 0; пользователь подтвердил, что подключит
  его самостоятельно. До подключения дизайн-этапы (3–5) используют
  `frontend-design` как указано в исходном ТЗ (раздел 4.1).
- **ASSUMPTION**: `docs-src/source/MAIN.md` и `carbon_footprint_dev_spec.md`
  не предоставлены — формулы и поля берутся из раздела 5 исходного ТЗ
  (`PROMPT_CLAUDE_CODE.md`) дословно, как это прямо разрешено автором ТЗ.
- **ASSUMPTION**: `Decimal` vs типизированный `float` для расчётного ядра —
  решение откладывается до начала Этапа 1, когда будет виден объём
  вычислений и тестовых golden-кейсов (см. ADR-0001).

- **ASSUMPTION**: `mkdocs-git-revision-date-localized-plugin` имеет
  собственную опцию `strict` (по умолчанию `true`), из-за которой
  предупреждение «no git logs» для каталога `docs` (ожидаемо на первом
  коммите/пустой истории) эскалируется и ломает `mkdocs build --strict`.
  Выставлено `strict: false` в конфиге плагина в `mkdocs.yml` — внешний
  флаг `mkdocs build --strict` (контроль качества самой документации)
  не затрагивается, глушится только самодиагностика плагина по git-истории.

## Разрешено после Stage 0

- `impeccable` стал доступен (установлен и настроен пользователем между
  сессиями — `apps/web/PRODUCT.md`, `.impeccable/config.json` созданы
  командой `/impeccable init`). Дизайн Этапов 3–5 выполнен с применением
  `craft-floor.md` инлайн по ходу написания компонентов, но без полного
  интерактивного `impeccable audit`/`polish` прохода — см. ниже.
- **ASSUMPTION** (Stage 1): выбран `Decimal` для внутренней арифметики
  ядра — зафиксировано как [ADR-0002](architecture/adr/0002-decimal.md).

## Stage 2 — Backend

- **ASSUMPTION**: ротация refresh-токена при каждом использовании не
  реализована — `POST /auth/refresh` перевыпускает access-токен, но не
  инвалидирует старый refresh-токен и не выдаёт новый. Для демо-прототипа
  это приемлемо; для продакшена нужна полноценная ротация с чёрным
  списком использованных токенов.
- **ASSUMPTION**: rate limiting на `/auth/*` — in-memory (`slowapi`),
  не переживает перезапуск процесса и не синхронизируется между
  инстансами. Для single-instance демо — ок; для масштабирования нужен
  Redis-бэкенд.
- `AuditLog` создан в схеме БД, но запись в него при финализации
  расчёта и выгрузке отчётов не подключена ни к одному эндпоинту.
- Флаг «коэффициент старше 5 лет» (`factor_max_age_years` в
  `config/hotspots.yml`) определён, но не подключён к реальной проверке
  возраста по `EmissionFactor.year` в `hotspots.py`.
- Отраслевой ориентир (бенчмарк) для hotspots — справочник не создан
  (по требованию «если ориентира нет — блок скрывается, не
  выдумывается»), поэтому блок сравнения с ориентиром отрасли сейчас
  всегда отсутствует в выводе, а не «временно пуст».
- Полный режим мастера (разделы 0–8 исходного ТЗ, кроме уже покрытого
  быстрым режимом) не имеет UI — поля доступны через прямой вызов
  `PATCH /calculations/{id}` с произвольным JSON (валидируется той же
  Pydantic-схемой), но форма для них не построена.
- `GET /calculations/{id}` и `PATCH /calculations/{id}` возвращают
  `dict[str, Any]` (не Pydantic `response_model`) — OpenAPI-схема для
  них нетипизирована; фронтенд использует собственные ручные типы
  (`apps/web/lib/types.ts`). Если проект продолжится, стоит завести
  явные response_model для точной типизации в `packages/contracts`.

## Stage 4–5 — Фронтенд

- Регион компании из профиля не подставляется автоматически как
  электроэнергетический регион по умолчанию в новом расчёте (была
  такая механика в старом прототипе) — в этой версии пользователь
  выбирает регион в мастере заново на каждый расчёт.
- `components/ui/` — собственные примитивы вместо shadcn/ui CLI —
  зафиксировано как [ADR-0003](architecture/adr/0003-frontend-primitives.md).
- `next-intl` не подключён для единственной локали —
  [ADR-0004](architecture/adr/0004-i18n.md).

## Stage 6 — Демо-готовность

- Playwright e2e-тест и скрипт генерации скриншотов для
  `docs/user-guide/` — не реализованы, см.
  [ADR-0005](architecture/adr/0005-deferred-e2e-and-docs-screenshots.md).
- Регулярные бэкапы БД — не настроены (см. `docs/operations/index.md`).

Вопросы без очевидного default-варианта будут добавляться сюда по мере
реализации следующих этапов.
