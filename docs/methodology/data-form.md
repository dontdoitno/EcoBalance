# Форма сбора данных (мастер)

Реализованы **два режима**, как и предусматривало исходное ТЗ (§5.3):

## Быстрый режим (реализован полностью)

`apps/web/app/calculations/[id]/page.tsx`. Четыре шага:

1. **Продукт** — выбор продукта (`/reference/products`) и, если у
   продукта есть маршруты, технологического маршрута (`/reference/routes`).
2. **Сырьё и энергия** — одна строка сырья (`/reference/raw-materials`)
   с расходом на функциональную единицу, электроэнергия (МВт·ч/т) и
   регион энергосистемы (`/reference/regions`).
3. **Транспорт** (опционально) — ноль или больше плеч: вид транспорта
   (`/reference/transport-modes`), расстояние, масса.
4. **Подтверждение** — сводка перед расчётом.

Поля сохраняются черновиком через `PATCH /calculations/{id}` на каждом
переходе между шагами (автосохранение); при возврате на страницу расчёт
подгружается через `GET /calculations/{id}` и форма восстанавливается.

## Полный режим (разделы 0–8)

**Не реализован в этой версии.** Ядро (`ecobalance_core.models.CalculationInput`)
уже поддерживает большинство полей полного режима — топливо с явным
НТС/EF, несколько видов сырья, тепло с собственной котельной,
технологические/факельные/фугитивные выбросы, несколько транспортных
плеч, отходы и сточные воды, сопряжённые продукты с аллокацией, GWP
AR5/AR6, границы системы (`cradle_to_gate`/`cradle_to_border`/`cradle_to_grave`),
качество данных (`DataQualityInput`). Чего не хватает — это:

- UI-формы для разделов 2 (топливо отдельно от сырья), 4 (факелы/
  фугитивные/N₂O), 6 (отходы), 7 (сопряжённые продукты/аллокация),
  8 (качество данных) — сейчас эти поля достижимы только через прямой
  вызов API (`PATCH /calculations/{id}` с произвольным JSON,
  валидируемым той же Pydantic-схемой), не через мастер;
- отдельных полей раздела 0 (ИНН с контрольной суммой, контактное лицо,
  отчётный период, цель расчёта) как структурированных колонок — они
  не входят в `CalculationInput` (который описывает только расчётную
  модель, не метаданные компании/периода).

Зафиксировано как явный открытый пункт в `docs/open-questions.md`, а не
скрыто.

## Единицы измерения полей (быстрый режим)

| Поле | Единица |
|---|---|
| Расход сырья | т на функциональную единицу |
| Электроэнергия | МВт·ч на функциональную единицу |
| Расстояние транспорта | км |
| Масса транспорта | т на функциональную единицу |

Конвертация единиц — в `ecobalance_core/units.py`; несовпадение единиц
(например, попытка передать тонны там, где ожидается НТС) приводит к
явной ошибке, а не к тихому приведению.
