# Аллокация между сопряжёнными продуктами

Реализация: `apps/api/ecobalance_core/allocation.py`. Применяется только
когда расчёт содержит `co_products` — иначе `allocation_factor = 1`
(весь след относится на основной продукт).

Пользователь **обязан** указать метод и текстовое обоснование
(`AllocationInput.rationale`) — без него валидация `CalculationInput`
падает, если указаны сопряжённые продукты (`CalculationInput`'s
model-level validator). Магическое «без обоснования» запрещено намеренно.

## Четыре метода

| Метод | Формула фактора | Требует |
|---|---|---|
| `mass` | $\dfrac{M_{main}}{M_{main} + \sum M_{co}}$ | только массы (т/год) |
| `energy` | $\dfrac{M_{main} \times E_{main}}{M_{main} \times E_{main} + \sum (M_{co} \times E_{co})}$ | энергосодержание (ГДж/т) основного и всех сопряжённых продуктов |
| `economic` | аналогично `energy`, но с экономической стоимостью (валюта/т) | стоимость основного и всех сопряжённых продуктов |
| `system_expansion` | `factor = 1` (вся площадочная эмиссия — на основной продукт); вместо аллокации считается **кредит** за замещаемый продукт | количество и EF замещаемого продукта |

Для `mass`/`energy`/`economic` фактор всегда в `[0, 1]` — доказано
property-тестом (`test_mass_allocation_factor_is_bounded`) на случайных
массах.

## System expansion — особый случай

$$
E_{credits} = Q_{substituted} \times EF_{substituted}
$$

Кредит вычитается из итогового следа **после** аллокации
(`engine.py`: `pcf_full = allocated − allocation_credit`), а не заменяет
её — основной продукт несёт всю площадочную эмиссию, но получает скидку
за то, что замещает производство другого продукта где-то ещё.

## Открытый вопрос

Выбор метода аллокации — продуктовое решение пользователя для каждого
расчёта; справочник «типичного» метода по продукту/маршруту не включён
в эту версию (см. `docs/open-questions.md`).
