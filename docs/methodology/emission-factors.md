# База коэффициентов выбросов

**Большинство коэффициентов в этой версии — демонстрационные
(`is_demo=True`), не верифицированы ни по одной реальной базе данных
(Ecoinvent, Carbon Minds, GaBi, Росстат и т.п.).** Каждый коэффициент
несёт `source`, `year`, `is_demo` на уровне кода
(`ecobalance_core/reference.py`) и на уровне БД (`EmissionFactor`,
заполняется `scripts/seed.py`). UI и отчёты показывают demo-факторы
явным предупреждением (`demo_factors` data-quality flag, баннер на
страницах результатов/сценариев и в самих отчётах).

**Исключение: `FUELS`** — коэффициенты по топливу взяты из
Table 4-7/4-8 (Annex D) *EU CBAM Guidance Document 3* (стандартные
значения IPCC 2006 Guidelines), `source="EU CBAM Guidance No.3 Annex D
(IPCC 2006 GL)"`, `is_demo=False` для всех позиций, кроме `hydrogen`
(нулевой EF, не из этой таблицы). `biomass` оставлен с EF=0 по
конвенции GHG Protocol о биогенном CO₂ — IPCC даёт «preliminary EF» до
вычета биогенной доли, этот показатель намеренно не копируется как
итоговый коэффициент сгорания.

### Регионы энергосистемы: обновление с atsenergo.ru

`REGIONS` переструктурирован с устаревшей группировки «ОЭС» на
реальные ценовые/неценовые зоны atsenergo.ru («Коэффициент выбросов
парниковых газов энергосистемы России»). Источник — файл
`CARBON_plan_hour_15.11.2026_15.11.2026.csv`, выгруженный с сайта
вручную (экспорт «Плановые значения» → почасовые данные за один день,
т.к. сайт отдаёт эти данные только через xls/csv/xml, не в статичном
HTML). Значение EF каждой зоны в коде — **среднесуточное** за
2026-11-15 по колонке `K (CO2e), кг CO2e/МВт·ч` (включает CO₂+CH₄+N₂O),
не верифицированное годовое значение — это осознанное ограничение
(план на один день, не факт за год).

Покрыты зоны: «Первая ЦЗ (Европа и Урал)» (332,44), «Вторая ЦЗ
(Сибирь)» (452,09), «Вторая ЦЗ (Восток)» (517,93), «НЦЗ Калининградской
области» (561,26). Зоны, которых не было в этой выгрузке (НЦЗ
Архангельской области, НЦЗ Республики Коми, изолированные ТИТЭС
Камчатского края/Сахалинской области/Магаданской области/Чукотского
АО) остаются одним демо-плейсхолдером `isolated` (650, `is_demo=True`)
с явной пометкой «требует проверки» — нужен отдельный проход с
выгрузкой «Фактические значения» (годовые/месячные), покрывающей эти
зоны.

## Версионирование и воспроизводимость

Каждый `Calculation` хранит `factor_version` (сейчас фиксированная
строка `"demo-2024"`); при появлении второй версии справочника это
поле позволит воспроизвести расчёт на той версии коэффициентов, с
которой он был сделан изначально (`PROMPT_CLAUDE_CODE.md` §6: «снимок
входных данных и версии справочника коэффициентов для
воспроизводимости»). Полноценный механизм версионирования нескольких
одновременно живущих версий справочника — не реализован (одна «живая»
версия на данный момент).

## Замена на верифицированные данные (следующий шаг)

Замена демо-коэффициентов на реальные — отдельная задача, не
выполненная в этой версии: нужен реальный источник (поставщик базы
данных ещё не определён в проекте), процесс обновления `EmissionFactor`
без потери воспроизводимости старых расчётов, и снятие флага
`demo_factors` только для записей, которые были фактически заменены.
