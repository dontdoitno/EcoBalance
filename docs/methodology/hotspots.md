# Hotspots: критерии и пороги

Реализация: `ecobalance_core/hotspots.py`, конфигурация —
`apps/api/config/hotspots.yml` (не хардкод в коде).

## Ранжирование по вкладу (Парето)

```yaml
thresholds:
  critical_pct: 30
  significant_pct: 15
```

Каждая статья разбивки (`BreakdownItem`) получает рейтинг:

- **Критический** (`critical`) — вклад ≥ 30%.
- **Значимый** (`significant`) — 15–30%.
- **Низкий** (`low`) — иначе.

Пороги видны в коде только как имена ключей конфига — значения можно
поменять без релиза.

## Специфика химической отрасли

```yaml
scope3_chemical_hint_pct: 64
```

Если Scope 3 превышает 64% от полного следа, добавляется
информационный флаг: «Scope 3 составляет X% от следа — выше, чем в
среднем по химической отрасли (ориентир ~64%)». Цифра 64% —
иллюстративная, взята из исходного технического задания без отдельной
верификации (см. `PROMPT_CLAUDE_CODE.md` §7.4).

## Флаги качества данных

См. [data-quality.md](data-quality.md) — пороги в том же файле
конфигурации (`quality_flags`).

## Не реализовано

- Сравнение с отраслевым ориентиром для продукта/маршрута (§7.3
  исходного ТЗ: «если ориентир есть в справочнике; иначе блок
  скрывается, ничего не выдумывать») — справочник ориентиров не создан
  в этой версии, поэтому блок **всегда скрыт**, что соответствует
  требованию «ничего не выдумывать», но сам ориентир пока не внесён.
- Отдельный CBAM-специфичный вид hotspots (разбивка только Scope 2 +
  прекурсоры) — в API/ядре это доступно через `cbam_embedded` и
  `breakdown` с категорией `upstream`, но отдельного UI-представления
  «CBAM hotspots» не выделено — используется тот же список hotspots,
  что и для PCF.
