# Русификация терминов под регуляторику РФ

Документ фиксирует, как привести названия полей, статусов и терминов
интерфейса в соответствие с нормативной базой РФ по выбросам парниковых
газов, не теряя при этом совместимость с международными стандартами
(ISO 14064/14067, GHG Protocol) и данными для CBAM/ТУМ ЕС, на которых
построено расчётное ядро.

## Принцип

- **Пользовательский слой** (UI-копия, отчёты, документация) —
  русифицируется полностью, с опорой на термины из 296-ФЗ, ГОСТ Р ИСО
  14064-1—2020, ГОСТ Р ИСО 14067-2021 и методических указаний Минприроды.
- **Технический/идентификационный слой** (внутренние ключи `measure_id`,
  `category`, ISO/GWP-наборы, коды ТН ВЭД для CBAM) — **не переводится**.
  Коды ТН ВЭД и ссылки на ISO-стандарты обязаны оставаться в исходном
  виде, иначе отчёт теряет юридическую узнаваемость для таможенных и
  регуляторных органов.

## Таблица соответствия терминов

| Международный термин / код | Текущее отображение в UI | Рекомендуемый термин РФ-регуляторики | Источник |
|---|---|---|---|
| Scope 1 / Scope 2 / Scope 3 | `Scope 1/2/3` (как есть) | Область охвата 1 / 2 / 3 (прямые / косвенные энергетические / прочие косвенные выбросы) | ГОСТ Р ИСО 14064-1, п. 3.1.1–3.1.3 |
| GWP (Global Warming Potential) | `AR5` / `AR6` (как есть) | Потенциал глобального потепления (ПГП), наборы МГЭИК AR5/AR6 | Приказ Минприроды России, методика расчёта выбросов ПГ |
| PCF (Product Carbon Footprint) | «Углеродный след продукции» (уже локализовано) | без изменений | ГОСТ Р ИСО 14067-2021 |
| CBAM (Carbon Border Adjustment Mechanism) | «CBAM» (как есть) | Механизм трансграничного углеродного регулирования ЕС (СВАМ/ТУМ), обязательно с пояснением «CBAM» в скобках при первом упоминании | официальный перевод в разъяснениях Минэкономразвития/ФТС |
| Functional unit | «Функциональная единица» (уже локализовано) | без изменений | ГОСТ Р ИСО 14067-2021, п. 3.3 |
| Emission factor | «Коэффициент выбросов» (уже локализовано) | без изменений | 296-ФЗ, ст. 3 |
| System boundary (`cradle_to_gate` и т.д.) | англ. значения enum, лейблы уже переведены | оставить англ. ключи enum, лейблы — «от сырья до ворот завода» и т.п. (уже реализовано, см. `BOUNDARY_LABEL` в `reports/page.tsx`) | — |
| Allocation (mass/energy/economic/system expansion) | «Коэффициент аллокации» (уже локализовано) | добавить метод аллокации словом, не только числом: «по массе» / «по энергосодержанию» / «по стоимости» / «расширение системы» | ГОСТ Р ИСО 14044 |
| Hotspot | «Слабое место» / «карта слабых мест» (уже локализовано) | без изменений | — |
| CN code (код ТН ВЭД) | `cn_code` (например `2814 10 000`) | **не переводить**, оставить ТН ВЭД-код как есть — это юридический идентификатор для таможни ЕС и ФТС России | Постановление Правительства РФ о гармонизированной системе |
| `is_demo` / «демо-коэффициенты» | уже на русском | без изменений, но стоит явно писать «не верифицировано для подачи декларации» (уже сделано в баннере) | — |

## Что уже сделано правильно (не трогать)

- Названия продуктов, маршрутов, видов топлива, регионов (ОЭС),
  транспорта и методов утилизации отходов в `ecobalance_core/reference.py`
  уже на русском языке во втором поле (`name`) — англоязычные
  `snake_case`-идентификаторы в первом поле (`id`) используются только
  как внутренние ключи и никогда не показываются пользователю напрямую.
- Каталог мер (`config/measures.yml`) и справочник ОЭС-регионов уже
  полностью русифицированы.
- CN-коды (`cn_code`) в `PRODUCTS` оставлены в оригинальном формате ТН
  ВЭД ЕС — это обязательное требование для CBAM-отчётности, менять
  нельзя.

## Что стоит доперевести/доформулировать

1. **`gwp_set`** в отчётах (`reports/page.tsx`, `MetaRow`) выводит
   `"AR5"`/`"AR6"` без расшифровки — добавить подпись «(набор МГЭИК)».
2. **Названия статусов расчёта** (`draft` / `final`) в `CalculationDetail`
   отображаются напрямую в части служебных экранов — свести к единому
   словарю `dict.common.status.{draft,final}` → «Черновик» / «Финализирован».
3. **Роли пользователей** (`company_user` / `admin`) в бэкенде не имеют
   русских лейблов во фронтенде (если роль когда-либо показывается в UI) —
   завести `dict.common.role.*`.
4. **Allocation method** — числовой коэффициент аллокации сейчас
   показывается без названия метода; нужно прокидывать `rationale`/метод
   из `ecobalance_core/allocation.py` в `CalculationResult` и выводить
   его текстом рядом с процентом (см. пункт выше в таблице).
5. **Единицы измерения** (`t`, `kg`, `m3`) в `functional_unit` сейчас
   выводятся как сырые enum-значения в части мест — свести к единому
   `dict.common.unit.{t,kg,m3}` → «т» / «кг» / «м³».

## Как вносить изменения

- Все пользовательские строки — только через `apps/web/lib/dictionaries/ru.ts`
  (см. [ADR-0004](../architecture/adr/0004-i18n.md)), никаких строк
  напрямую в JSX.
- Технические идентификаторы (`id`, enum-значения, `category`, `measure_id`,
  CN-коды) не переводятся никогда — это контракт между фронтендом,
  бэкендом и внешними регуляторными форматами.
- При добавлении нового термина сверяться с этой таблицей и, если термин
  отсутствует, добавлять его сюда вместе со ссылкой на источник
  (ГОСТ/ФЗ/методика), а не переводить «на слух».
