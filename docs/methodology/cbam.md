# CBAM: встроенные выбросы

CBAM считает **embedded emissions** = прямые выбросы производства
(Scope 1) + косвенные от потреблённой электроэнергии (Scope 2) +
выбросы производства сырья-прекурсоров (Scope 3, только upstream).
**Транспорт готовой продукции до границы и отходы в CBAM-значение не
входят** — в отличие от полного PCF (ISO 14067), который учитывает все
Scope 1–3.

Ядро разводит два результата на уровне одного вызова
`engine.calculate`:

```python
result.pcf_full_kg_co2_per_unit       # все Scope 1-3
result.cbam_embedded_kg_co2_per_unit  # Scope 1 + Scope 2 + upstream; None, если продукт не CBAM-применим
result.cbam_applicable                # bool
result.cbam_not_applicable_reason     # заполнено, если cbam_applicable=False
```

API и UI повторяют это разведение: `/reports/{id}?report_type=cbam`
возвращает `409` с объясняющим сообщением, если продукт не
CBAM-применим, вместо того чтобы незаметно подменить его PCF-отчётом.

## Применимость по категориям товаров

CBAM покрывает категории: цемент, удобрения, железо и сталь, алюминий,
водород, электроэнергия. Из демо-каталога продуктов EcoBalance (см.
[emission-factors.md](emission-factors.md)) под категорию «удобрения»
попадают **аммиак, мочевина, сульфат аммония** — у них
`cbam_applicable=True` и указан CN-код (`reference.PRODUCTS`). Этанол,
полиэтилен, ПВХ, ацетон под действующие категории CBAM не подпадают —
для них UI показывает «CBAM не применим» и предлагает PCF-отчёт.

Таблица соответствия продукт → применимость → CN-код хранится в
`ecobalance_core/reference.py` (`Product.cbam_applicable`,
`Product.cn_code`) — **сверить с актуальным регламентом перед
использованием в реальных декларациях**; текущие значения заданы по
исходному ТЗ без дополнительной верификации.

## Структура отчёта

Детальная структура и соответствие полей отчёта источникам данных — см.
[cbam-mapping.md](cbam-mapping.md). Порог применения CBAM (импорт ≥ 50
т/год товаров CBAM) показывается в UI как справочная информация, не как
ограничение расчёта.

## Оценка стоимости

Отчёт CBAM показывает два сценария:

```
стоимость = встроенные_выбросы (тCO₂-экв./т) × цена_квоты_EU_ETS (€/т)
```

— «фактические данные» (из расчёта) и «default-значение» (факт × (1 +
наценка)). Цена ETS и наценка — настраиваемые параметры запроса
(`ets_price_eur_per_t`, `default_markup_pct` в `/reports/{id}`), не
константы в коде. Та же механика на лендинге — интерактивный
мини-калькулятор «сколько вы теряете без первичных данных»
(`components/landing/mini-calculator.tsx`).
